# 缓存与传输策略

HTML 需要较快发现新版本，通常短缓存或协商缓存；带 content hash 的 JS/CSS/图片内容不变则 URL 不变，可长期 immutable 缓存。发布时先上传新静态资源，再切换 HTML，并保留旧资源，避免旧页面或缓存 HTML 请求不到 chunk。

Brotli 通常压缩文本更好，gzip 兼容广，服务端应根据 `Accept-Encoding` 返回已预压缩产物。图片、视频等已压缩格式再次压缩收益很小。

CDN 缓存减少回源和地理延迟，浏览器缓存减少用户网络请求，Service Worker 提供可编程离线/更新策略。三层要有清晰版本和失效协议。

HTTP/2/3 支持复用后，为减少连接而合并所有资源、做大量域名拆分的旧策略可能适得其反；仍应根据压缩、缓存边界和优先级分块。304 不传响应体，但仍有一次网络往返，稳定 hash 资源可直接 fresh cache。

`stale-while-revalidate` 适合允许短暂旧值的静态资源或数据。观测时区分浏览器命中、CDN hit/miss、回源量、age 和重新验证，单看服务器流量无法得出完整命中率。
