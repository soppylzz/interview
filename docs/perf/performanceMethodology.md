# 性能优化方法论

性能优化先回答三个问题：哪个用户场景慢、用什么指标描述、瓶颈发生在哪里。直接罗列懒加载、缓存和压缩无法证明解决了真实问题。

## 性能维度

- 加载性能：内容和关键资源何时到达。
- 运行时性能：脚本、样式、布局和绘制成本。
- 交互响应：输入到下一次视觉反馈的延迟。
- 内存：占用、峰值、泄漏与回收停顿。
- 稳定性：波动、错误和长尾设备表现。

实验室数据环境可控，适合复现与诊断；RUM 来自真实设备、网络和行为，适合判断用户影响。平均值会掩盖少数极慢体验，P50 描述典型用户，P75 常用于体验目标，P95 暴露长尾。分位数必须同时按页面、设备、网络和版本切分。

## 闭环

1. 固定用户路径并建立基线。
2. 用 waterfall、trace、profile 和 RUM 分解网络、后端、主线程、渲染与内存。
3. 提出只针对瓶颈的改动。
4. 在同等条件复测，并观察线上分位数和副作用。
5. 把资源、主线程或体验指标写入预算，防止回退。

最后按受影响用户数、收益、实现风险和长期维护成本排序。一个只改善跑分却增加产品复杂度的方案未必值得实施。
