# 运行时列表与大量 DOM

大量 DOM 增加节点内存、样式匹配、布局、绘制和更新成本。虚拟列表只挂载可视区域及少量 overscan，把成本从总数据量降到窗口大小。

固定高度列表可由索引直接计算 offset；动态高度需要测量、缓存高度和维护前缀和，并在高度变化时修正滚动锚点。overscan 太小快速滚动会白屏，太大会失去虚拟化收益，应按设备和滚动速度调节。

分页适合有明确页与搜索语义的内容；无限滚动适合连续浏览；虚拟列表适合单页必须承载大量数据。它们可组合，但要保留键盘、焦点、查找和可访问性。

DocumentFragment 能减少某些逐次插入过程，但现代框架已有批处理，且真正成本可能在样式/布局；需要 profile 后决定。事件委托用一个祖先监听器处理大量相似子项，可减少监听器和清理成本。

DOM 适合可访问、可交互普通界面；SVG 适合数量适中的矢量元素；Canvas 适合海量绘制，但命中测试、语义和可访问性需自行实现。
