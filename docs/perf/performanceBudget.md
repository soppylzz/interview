# 性能预算与自动化

性能预算把“不要变慢”变成可检查约束。预算可以覆盖：

- 资源：关键 JS/CSS、图片和总传输体积。
- 数量：首屏请求、第三方域名或 chunk 数量。
- CPU：Long Task、脚本执行或主线程时间。
- 体验：LCP、INP、CLS 等 RUM 分位数。

构建时 bundle size check 能快速阻止明确体积回退，Lighthouse CI 能在受控页面检测综合趋势，线上 RUM 告警负责真实设备和长尾。三者互补，构建通过不代表真实体验一定稳定。

实验室分数受机器、网络、缓存和服务端波动影响。CI 应固定环境、预热或明确冷启动、多次运行取中位数，并为噪声设置合理容差；只有持续、超出波动范围且能归因到提交的变化才作为回退。

预算应按页面模板和设备档位制定，保留基线、目标、负责人和例外到期时间。第三方或框架升级也要进入 bundle diff、关键 trace 和页面测试，不能因它来自依赖就排除。

预算失败时输出新增模块、资源差异和指标变化，让开发者能行动；只有一个红色分数的门禁很快会被忽略。
