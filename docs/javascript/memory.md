# 内存与垃圾回收

对象通常分配在受管理 heap，调用信息保存在执行栈；具体布局属于引擎实现。GC 根据从全局、活动栈等 root 出发的可达性回收对象，而不是根据“以后是否还会用”。

现代引擎常使用分代、增量、并发等策略，但面试无需把某个 V8 版本细节当语言保证。频繁分配会增加 GC 工作，长生命周期大缓存会推动对象存活。

常见泄漏来源包括无界全局集合、未清 timer/监听器、闭包保留大对象、detached DOM、未终止 Worker/Observer。WeakMap 只弱持有 key，并不自动清理其他外部资源。

判断泄漏要重复同一操作并比较 GC 后基线；Heap Snapshot 用 retaining path 找引用链，Allocation Timeline 找分配位置。瞬时峰值和合理缓存不等于泄漏。
