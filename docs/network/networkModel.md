# 网络分层模型

> 分层把复杂通信拆成若干职责稳定的协议层。发送方逐层封装，接收方逐层解封装。

## 1. OSI 与 TCP/IP

| OSI 七层 | TCP/IP 常用模型 | 典型协议或数据 |
| --- | --- | --- |
| 应用层、表示层、会话层 | 应用层 | HTTP、DNS、TLS、WebSocket |
| 传输层 | 传输层 | TCP、UDP、QUIC |
| 网络层 | 网际层 | IPv4、IPv6、ICMP |
| 数据链路层、物理层 | 网络接口层 | Ethernet、Wi-Fi、ARP |

OSI 更适合帮助理解职责，互联网实际协议通常使用 TCP/IP 模型描述。TLS 常被描述为位于 HTTP 与 TCP 之间，但不必强行给它指定唯一的 OSI 层级。

## 2. 各层职责

### 应用层

定义应用之间交换信息的语义。例如 HTTP 定义请求方法、状态码和首部，DNS 定义域名查询。

### 传输层

负责端到端进程通信。TCP 提供可靠有序字节流；UDP 提供保留消息边界的数据报。

### 网际层

IP 根据目标地址跨网络转发数据包，但不保证送达、顺序或只送达一次。

### 网络接口层

负责同一链路上的帧传输。以太网使用 MAC 地址，ARP 可在 IPv4 局域网中查询下一跳的 MAC 地址。

## 3. 标识如何配合

- 域名：供人使用的资源命名，通过 DNS 找到地址。
- IP 地址：标识网络中的接口，用于路由。
- 端口：标识主机上的通信端点或服务。
- MAC 地址：用于本地链路上的帧交付。
- URL：描述协议、主机、端口和资源位置。

一个 TCP 连接通常用五元组区分：源 IP、源端口、目标 IP、目标端口、传输协议。

## 4. Socket

Socket 是操作系统提供的网络通信抽象。应用通过 socket 执行 bind、listen、connect、accept、send、receive 等操作，而不直接控制每个 TCP/IP 报文字段。

服务端通常把监听 socket 绑定到本地 IP 和端口。每次接受 TCP 连接后，系统创建一个新的已连接 socket；监听 socket 继续接收后续连接。

## 5. 封装与解封装

发送 HTTP 请求时，可以将数据理解为：

```text
HTTP message
  -> TLS record
    -> TCP segment / QUIC packet
      -> IP packet
        -> link frame
```

每层添加本层控制信息。接收端验证并去除这些信息，把上层数据交给对应协议处理。分层是逻辑模型，真实实现可能进行分段、合并、硬件卸载等优化。

## 6. 一次请求使用的协议

以 HTTP/2 over TLS 为例：

1. DNS 将域名解析为 IP。
2. IP 负责把数据包路由到目标网络。
3. TCP 建立可靠字节流。
4. TLS 在字节流上协商密钥并保护数据。
5. HTTP/2 在 TLS 通道中传递帧、请求和响应。

HTTP/3 则让 HTTP 运行在 QUIC 上。QUIC 基于 UDP 数据报实现可靠传输，并集成 TLS 1.3。

## Interview

### IP 地址和端口分别解决什么问题？

IP 地址用于将数据路由到目标主机或网络接口，端口用于把到达主机的数据交给正确的进程或 socket。

### 为什么需要分层？

分层降低耦合。应用可以使用 HTTP，而不必关心底层是 Ethernet 还是 Wi-Fi；传输协议也不必理解 HTTP 的业务语义。代价是额外首部、跨层优化困难以及部分职责可能重复。
