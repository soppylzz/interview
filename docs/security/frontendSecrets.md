# 前端秘密与加密误区

发到浏览器的 bundle、source map、网络请求和运行时内存都受用户控制，因此 API secret、私钥和长期服务凭证不能放客户端。环境变量前缀只控制注入规则，不提供保密。

压缩、混淆、Base64 和自定义算法只能提高阅读成本，不是密码学保护。真正秘密留在服务端，用短期、受限、可撤销凭证把必要能力授权给客户端。

Web Crypto 适合标准加密、签名验证和密钥派生，但密钥来源与存储决定安全性。浏览器端加密可保护用户口令派生数据或端到端内容，却不能对控制页面脚本的攻击者隐藏明文。

使用 `crypto.getRandomValues` 生成安全随机数，不用 Math.random 创建 token。TLS 保护传输；应用层加密解决不同威胁，不能以重复加密替代身份和授权。
