# JavaScript 项目渐进迁移

`allowJs` 让 JavaScript 文件进入 TypeScript program，`checkJs` 对它们执行检查；单文件可用 `// @ts-check` 开启。JSDoc 的 `@param`、`@returns`、`@typedef`、`@template` 能在不改扩展名时增加类型。

## 错误抑制

- `@ts-expect-error` 要求下一行确实存在错误；错误消失时自身报错，适合有期限的临时兼容和负向类型测试。
- `@ts-ignore` 无论是否还有错误都静默忽略，更容易永久残留。
- `@ts-nocheck` 关闭整个文件检查，只适合短期隔离最难迁移文件。

抑制注释应记录原因、负责人或删除条件，防止成为无边界逃生口。

## 迁移顺序

1. 建立可运行的 typecheck，并开启 allowJs。
2. 先给网络、存储、公共函数和模块出口定义类型。
3. 用运行时校验保护外部输入。
4. 从依赖少、测试充分的叶子模块改成 `.ts`。
5. 按选项逐步开启 strict，记录基线并分批清理。

第三方包优先使用自带类型，其次安装匹配版本的 `@types`。确实无类型时写最小临时 `declare module` 只能止血，应逐步把 unknown/any 替换为真实 API 契约。

迁移期间应保持构建和测试持续通过，避免把“改扩展名”和业务重构塞进同一次变化，降低回归定位难度。
