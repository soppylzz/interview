# 微前端工程

微前端首先解决大型组织的独立开发和部署问题，运行时方案只是实现手段。如果团队无法真正独立发布或领域边界不清，拆分可能只增加协调成本。

## 集成方案

| 方案 | 特点 |
| --- | --- |
| iframe | 隔离最强，跨上下文通信、路由和体验整合较重 |
| 运行时集成 | 独立部署灵活，需要治理依赖、样式和生命周期 |
| 构建时集成 | 类型和优化容易统一，但发布耦合更强 |
| Web Components | 提供元素和样式封装，状态与依赖仍需约定 |

Module Federation 中 host 在运行时消费 remote 暴露模块，shared dependency 可复用宿主依赖。singleton 能避免 React 等出现多实例，但版本范围不兼容时必须定义升级、回退或隔离策略，不能只配置“共享”。

## 隔离与治理

样式可用命名空间、CSS Modules、Shadow DOM；全局变量应减少并建立沙箱或契约；路由需划分所有权；跨应用事件要有版本化 schema 和清理机制。统一鉴权、设计系统、错误监控和发布清单能维持整体体验。

成本包括重复依赖、额外请求、运行时编排、跨应用调试和版本矩阵。只有当团队边界、发布频率和独立演进收益足以覆盖这些成本时才值得引入。
