# Monorepo

Monorepo 把多个包放进一个版本库，便于原子变更、统一工具和代码复用；代价是仓库规模、权限边界、任务调度和缓存更复杂。Multirepo 隔离和独立发布更自然，但跨仓修改和版本协调成本更高。

## 两张依赖图

package dependency graph 描述包之间的引用；task graph 还包含 `build → test`、上游先构建等任务约束。调度器据此并行无依赖任务，并按拓扑顺序执行依赖任务。

affected 执行从变更文件映射到包，再沿反向依赖找受影响任务。缓存 key 应包括源码、依赖输出、命令、配置、环境和工具版本；远程缓存还需防止不同平台或秘密环境错误复用。

## 开发与发布

包可以直接消费同仓源码，开发反馈快但容易掩盖发布缺文件；也可以消费构建产物，更接近真实用户但需可靠 watch。TypeScript project references 能划分项目并复用增量结果。

统一版本发布便于兼容管理，独立版本减少无关发版。pnpm workspace 负责安装和本地链接，Nx/Turborepo 等更关注任务图、affected 和缓存；工具层次不应混为一谈。
