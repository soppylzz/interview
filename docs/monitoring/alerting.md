# 告警与异常聚合

Fingerprint 通常由错误类型、归一化 stack frame、组件/endpoint 组合；动态 id 和消息数值应规范化。Source map 后源码位置更稳定，但发布变化仍可能改变栈。

告警关注新错误、回归、错误率、受影响用户和业务影响，而不只事件总数。静态阈值适合明确 SLO，版本对比/同比适合流量周期，异常检测适合模式复杂指标。

设置最小样本、持续窗口、去抖、合并和维护期，防止告警风暴。每条告警有 owner、severity、runbook、相关 release/dashboard 和升级路径。

告警必须可行动；长期无人处理的告警应修规则或删除，而不是继续静音。
